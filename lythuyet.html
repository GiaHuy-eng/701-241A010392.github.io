Phần 1: Trả lời lý thuyết

Câu 1. position: absolute và position: relative

relativeabsolute
Luồng trangVẫn nằm trong luồng, chỗ cũ được giữBị rút khỏi luồng, không chiếm chỗ
Tọa độ top/left...Tính so với vị trí gốc của chính nóTính so với tổ tiên gần nhất có position khác static, nếu không có thì so với trang
Vai trò thường gặpLàm "mốc" cho phần tử con; dịch nhẹ phần tửĐặt chi tiết nhỏ: huy hiệu, nút đóng, chú thích đè lên ảnh

Tình huống và ví dụ responsive

Thẻ sản phẩm có huy hiệu "Mới" ở góc: thẻ là relative, huy hiệu là absolute nên luôn bám góc thẻ dù thẻ rộng hay hẹp. Phần bố cục lớn thì dùng Flexbox/Grid và media query:

.card{position:relative}
.badge{position:absolute;top:8px;right:8px}
.list{display:grid;grid-template-columns:repeat(auto-fill,minmax(200px,1fr));gap:12px}
@media (max-width:600px){.badge{font-size:.75rem}}

Không dùng absolute cho bố cục chính, vì phần tử bị rút khỏi luồng sẽ đè lên nhau khi màn hình hẹp.

Ảnh hưởng khi deploy

CSS do trình duyệt xử lý nên hosting không làm đổi cách position hoạt động. Điều cần kiểm tra sau khi deploy là hiển thị đúng trên nhiều thiết bị: có thẻ <meta name="viewport">, hạn chế px cố định kết hợp absolute, và thử bằng chế độ thiết bị của DevTools cùng điện thoại thật.

Câu 2. Domain, hosting, DNS và deploy

Quy trình

  1. Chọn và mua tên miền ở nhà đăng ký (PA Vietnam, Mắt Bão, Namecheap...).
  2. Đưa code (HTML/CSS/JS) lên dịch vụ hosting tĩnh.
  3. Vào trang quản lý domain, cấu hình DNS trỏ về hosting.
  4. Chờ DNS cập nhật (vài phút đến vài giờ), kiểm tra và bật HTTPS.

Vai trò của DNS

DNS dịch tên miền dễ nhớ thành địa chỉ IP của máy chủ để trình duyệt biết kết nối tới đâu.

Bản ghiTác dụng
ATrỏ tên miền tới một địa chỉ IPv4
CNAMETrỏ tên miền phụ (www) sang một tên miền khác, ví dụ ten-site.netlify.app
NSCho biết máy chủ DNS nào quản lý tên miền
TTLThời gian bản ghi được lưu đệm, quyết định thay đổi lan ra nhanh hay chậm

Công cụ deploy không cần server riêng

  • Netlify: kết nối repo GitHub, mỗi lần push tự động deploy, có HTTPS miễn phí và hỗ trợ gắn tên miền riêng.
  • GitHub Pages: bật Pages trong cài đặt repo, trang chạy ở địa chỉ username.github.io/ten-repo.

Rủi ro bảo mật nếu cấu hình sai

  • Không bật HTTPS: dữ liệu có thể bị nghe lén hoặc sửa trên đường truyền.
  • Đẩy nhầm khóa API, mật khẩu lên repo công khai: bị lộ và lạm dụng.
  • DNS trỏ sai hoặc bản ghi cũ còn sót: kẻ xấu có thể chiếm tên miền phụ (subdomain takeover).
  • Tài khoản hosting/domain không bật xác thực 2 lớp, quên gia hạn: bị chiếm quyền hoặc mất tên miền.

Câu 3. let, const và var

varletconst
ScopePhạm vi hàmPhạm vi khối { }Phạm vi khối { }
HoistingĐược đưa lên đầu, giá trị ban đầu là undefinedCó hoisting nhưng nằm trong "vùng chết tạm thời" (TDZ): dùng trước khai báo sẽ báo lỗiGiống let
Gán lạiĐượcĐượcKhông (nhưng nội dung object/mảng vẫn sửa được)
console.log(a); var a = 1;      // undefined
console.log(b); let b = 2;      // ReferenceError: Cannot access 'b' before initialization
const c = 3; c = 4;             // TypeError: Assignment to constant variable.

Lỗi thường gặp

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 100); // in 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 100); // in 0 1 2

var chỉ có một biến i dùng chung cho cả vòng lặp, khi callback chạy thì i đã bằng 3. let tạo biến i mới cho mỗi vòng nên in đúng 0 1 2.

Debug bằng Chrome DevTools

  1. Nhấn F12, mở tab Console để đọc thông báo lỗi và dòng gây lỗi.
  2. Mở tab Sources, bấm vào số dòng nghi ngờ để đặt breakpoint, rồi tải lại trang.
  3. Khi chương trình dừng, xem giá trị biến ở mục Scope hoặc thêm biểu thức vào Watch.
  4. Dùng Step over (F10) chạy từng dòng để thấy giá trị i đổi ra sao, từ đó phát hiện biến dùng chung.

Câu 4. Event Delegation

Là kỹ thuật gắn một trình nghe sự kiện lên phần tử cha thay vì gắn cho từng phần tử con. Nhờ event bubbling, sự kiện nổi từ con lên cha, và cha dùng event.target để biết con nào vừa được bấm.

const dl = document.getElementById("dl");
dl.addEventListener("click", e => {
  const li = e.target.closest("li");
  if (li && dl.contains(li)) li.classList.toggle("done");
});
// Thêm li mới bằng JS vẫn hoạt động, không cần gắn lại sự kiện

Lợi ích

  • Hiệu suất: danh sách 1000 mục chỉ cần 1 listener thay vì 1000, tiết kiệm bộ nhớ và thời gian khởi tạo.
  • Danh sách động: phần tử thêm sau tự có sự kiện, không cần gắn lại hay gỡ bỏ.
  • Kết hợp HTML/CSS: chỉ bật tắt class (như .done) rồi để CSS lo phần hiển thị; có thể dùng thuộc tính data-* trong HTML để biết phần tử nào được bấm.

Lưu ý

Sự kiện không nổi bọt (như focus, blur) cần dùng focusin/focusout; nếu mã con gọi stopPropagation() thì cha sẽ không nhận được sự kiện.
